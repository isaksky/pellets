# Installed Codex protocol adapter

`internal/codex` implements the process/protocol boundary for a future foreground
server runner. The inspector does not construct it yet. Queue, memory, and UI
use therefore neither probes Codex nor requires installation or authentication.
There is no Node/Python SDK, model/tool loop, daemon, or WebSocket client.

The contract follows the [official app-server documentation](https://learn.chatgpt.com/docs/app-server)
and was checked against the stable JSON schema generated by Codex CLI 0.151.0.
The executable's generated schema is authoritative when documentation and
runtime differ; for example, the actual user-input request method is
`item/tool/requestUserInput`.

## Process and compatibility

`Start(ctx, Config)` resolves the configured executable (`codex` by default),
executes `--version`, and asks that same executable to run
`app-server generate-json-schema --out <temporary-directory>`. It checks required
request methods and parameter names, required interaction methods, and terminal
notifications in the stable schema. Generation never opts into experimental
API fields. Missing capabilities produce `ErrUnsupported` with the executable,
version, and missing method/field; the caller can offer an upgrade or a different
executable. This is a focused capability check, not a complete JSON Schema
validator. Codex validates request values and returns structured RPC errors.

Only after this check does the adapter directly spawn
`codex app-server --listen stdio://`, complete `initialize` with Pellets client
metadata and `experimentalApi: false`, and send `initialized`. Global
configuration/feature arguments are supplied as separate array entries, before
the subcommand. Arguments never pass through a shell. The working directory and
optional environment additions are explicit; otherwise the child inherits the
installed runtime's configuration, credentials, instructions, and tools.
Pellets does not inject an approval or sandbox override.

Each probe and initialization have a 15-second timeout. The context passed to
`Start` owns the entire session lifetime, so use a run-lifetime context rather
than canceling it immediately after startup. `Close`, lifetime cancellation, or
a protocol failure closes the owned pipes, terminates the owned process family,
and waits for the app-server to be reaped. Cleanup failures remain visible through
`Close` and `Wait`. A child
exit allows the reader to drain terminal frames before final shutdown; leaked
inherited pipes are cut off after one second. Stderr is drained independently
into a bounded diagnostic tail and is never parsed as protocol JSON.

Every invocation, including version/schema probes, starts in a separate Unix
session. Normal Codex shell/PTY children create their own sessions with `setsid`,
so process-group termination alone is insufficient. The adapter tracks ancestry
using kernel process snapshots (`kern.proc` on macOS, `/proc` on Linux), retaining
PID plus process start time for each discovered descendant. Discovery runs every
20 milliseconds and synchronously before protocol messages reach the caller.
Known descendants remain owned after reparenting; inherited members of the
invocation's initial process group also remain discoverable after its leader
exits. Tracking is bounded to 4096 live process identities.

Cleanup first stops the live root, then repeatedly discovers and stops its
descendants until they can no longer fork. This happens before closing stdin
could induce an otherwise avoidable parent exit. It revalidates each process's
start time before sending an individual signal, kills descendants before the
root, and waits for them to exit or become non-running zombies. It never selects
processes by executable name or signals foreign process groups. Freeze and exit
observation each have a two-second bound, with errors reported by `Close`/`Wait`.

This is unprivileged lifecycle cleanup, not a kernel sandbox. macOS has no Job
Object/cgroup equivalent here: a descendant that both changes session and loses
all observed ancestors before any snapshot or protocol event can remain
unobservable. The adapter does not claim to contain arbitrary double-forking
daemons or forcibly interrupted Pellets processes. Normal `setsid` execution
with live or already-observed ancestry is covered, including app-server exit
after those descendants have been reported. PID/start-time checks also avoid
adopting unrelated processes when a recorded PID is reused.

On Windows, each invocation starts suspended, joins an
unnamed kill-on-close Job Object, and only then resumes its primary thread.
Assignment failure is fatal before runtime code executes. Descendants inherit
the job, breakaway is disabled, and cleanup waits up to two seconds for its active
process count to reach zero before reporting an error and closing the job.
The Windows implementation uses the documented
[Job Object lifecycle](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).

This ownership belongs to the protocol adapter because malformed transport or
failed initialization can terminate a session before a runner has an active
turn. The later foreground runner owns graceful turn interruption, durable run
outcomes, and restart policy; it must not be needed to clean up an adapter that
fails or is closed directly.

## Runner interface

The small `Session` interface provides `Call`, `Respond`, `Events`,
`LatestCompletion`, `Wait`, and `Close`. Request parameters/results and event
payloads retain Codex JSON rather than copying its large generated object model.
`Call` accepts only the named `Operation` constants:

| Concern | Operations |
| --- | --- |
| Conversation continuity | `thread/start`, `thread/read`, `thread/resume` |
| Active work | `turn/start`, `turn/steer`, `turn/interrupt` |
| Installed account and model state | `account/read`, `account/rateLimits/read`, `model/list` |
| Configuration | `config/read`, `configRequirements/read` |
| Separate or inline review | `review/start` with its explicit `target` and `delivery` |

For example, a caller can start a turn with this JSON-shaped payload:

```go
result, err := session.Call(ctx, codex.TurnStart, map[string]any{
    "threadId": threadID,
    "input": []any{map[string]any{"type": "text", "text": prompt}},
})
```

The event consumer must run concurrently with requests. Both numeric and string
server request IDs are retained exactly for `Respond`; client IDs are correlated
independently even when a server chooses the same numeric ID. Approvals,
permission requests, user questions, and MCP elicitation arrive as events with
an ID. The adapter never chooses an approval decision. The runner supplies the
runtime's result object or an `RPCError` (for example code `-32601` to reject an
unknown request). `serverRequest/resolved` removes outstanding requests, and
duplicate or already-resolved responses are rejected.

Concurrent calls may complete out of order. Canceling a call's context stops
local waiting and discards a later response; the operation may already have
reached Codex. The stable schema has no generic request-cancellation
notification. Remote work is stopped by `turn/interrupt` with `threadId` and
`turnId`, followed by observing `turn/completed`. Steering uses the required
`expectedTurnId` precondition. A graceful stop is a runner responsibility:
interrupt, observe the interrupted outcome, then close the session.

## Limits and outcomes

Defaults are 8 MiB per JSONL frame, 256 queued events, 128 outstanding client
requests, 128 outstanding server requests, and a 32 KiB stderr tail. The outgoing
queue has the same 128-message bound; a blocked pipe write times out after 15
seconds. Oversized frames and event/server-request overflow end the session with
an explicit error, rather than silently dropping activity or blocking responses
forever. Too many concurrent calls or an oversized outbound message reject that
call without terminating an otherwise healthy session. Limits are configurable.

Unknown optional notifications are delivered unchanged. Malformed JSON, invalid
IDs/envelopes, invalid terminal outcomes, invalid UTF-8, and an unterminated final
JSONL frame end the session and wake all pending calls. Unexpected EOF is a
transport error even when the process exits zero. `Wait` reports both transport
failure and process-exit error; a correlated reply already received wins over an
immediate process exit.

The event channel closes only after the reader finishes, and buffered events
remain drainable. `LatestCompletion` retains a defensive copy of the most recent
valid `turn/completed` payload, including when that event itself encounters an
overflow. It survives EOF and nonzero process exit. This bounded snapshot suits
a session scoped to one supervised run; a future runner sharing a session among
threads must persist each terminal event itself. An overflow is a transport
failure, never evidence that unseen work completed. Persist turn status/error
separately from the process outcome, and use conversation read/resume operations
to recover continuity when a terminal notification was never received.

## Verification

`go test ./internal/codex` uses scripted Go test subprocesses. It requires no
installed Codex, live credentials, model calls, or external network. Tests cover
handshake order, argument preservation, operation routing, interleaved events
and bidirectional requests, cancellation/interruption, limits, malformed/truncated
frames, startup errors, exit reaping, and terminal-event retention.
Descendant peers create a child and grandchild with independent readiness and
liveness checks; tests verify cleanup on close, lifetime cancellation, malformed
output, event overflow, parent exit, and probe exit/cancellation. Unix variants
call `setsid()` in both descendant generations and assert an unrelated detached
process remains alive. Identity tests cover PID reuse and orphaned sessions.

An explicit, optional smoke check validates the installed runtime and performs
initialization plus local configuration reads, without starting a model turn:

```text
PELLETS_CODEX_LIVE=1 go test ./internal/codex -run '^TestInstalledRuntime$' -v
```

Normal `go test ./...` skips that installed-runtime check.
